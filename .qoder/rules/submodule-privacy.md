# 子模块私有化规则

## 核心原则

`scripts/private` 是**私有仓库**，主仓库（RustLuaMud）是**公开仓库**。

隔离的目标是**不让公开侧泄露私有的业务实现，也不给外人无需凭据的下载入口**，而不是隐藏工程结构的存在。双编码体系（`class-utf8/` → `class/`）与钩子机制是本项目对外的核心工程特性，脱离这些路径根本无法描述；把它们也算作违规会让规则不可执行，进而被整体忽略。

## 三级分类

| 级别 | 内容 | 公开侧 |
|---|---|---|
| **L1 工程结构** | `scripts/private/` 挂载点、`scripts/class/`、`scripts/class-utf8/`、`hooks/`、`githooks/`、`.gitmodules` 中的子模块声明 | ✅ 允许 |
| **L2 机制性文件名** | 为让机制可执行而必须点名的私有侧文件，且**不附带业务语义**：同步规则里的加载清单路径、`.gitignore` 中被忽略的私有产物名、事故记录里用作定位坐标的文件名与行号、`src/` 注释里说明兼容层来源的文件名 | ✅ 允许 |
| **L3 业务实现** | 私有脚本的业务职责与游戏语义：任务/门派/收益/数值公式、游戏流程与调度策略、模块间调用关系、服务端逻辑；以及私有仓库的 raw URL 等可匿名访问入口 | ❌ 禁止新增 |

### 一句话判据

**能不能从这段文字还原出「游戏怎么玩」。**

| 写法 | 判级 |
|---|---|
| `class-utf8/fj.lua 由 iconv 生成 class/fj.lua` | L2 ✅ 只暴露编码机制 |
| `fj.lua 1152 行，护镖任务，70 个函数` | L3 ❌ 暴露业务职责 |
| `.gitignore` 里写 `xkxMAP.db` | L2 ✅ 只暴露有个被忽略的产物 |
| `xkxMAP.db 存入口房间坐标表，供 GPS 寻路查表` | L3 ❌ 暴露用途 |
| `事故：编辑 GBK 文件导致中文字节 corrupt` | L2 ✅ 只讲工程后果 |
| `事故：中文引号被改，导致押镖过河后无法交任务` | L3 ❌ 讲了业务后果 |

## 禁止行为

- **禁止**引用私有仓库的 raw URL（如 `raw.githubusercontent.com/<owner>/<private-repo>/...`）——这是无需凭据即可下载的入口
- **禁止**新增 L3 内容：私有脚本的业务职责、游戏数值/收益公式、任务流程与调度策略、服务端逻辑
- **禁止**在 CI/CD 配置中拉取或引用私有仓库内容
- **禁止**把私有脚本内容复制进公开仓库跟踪的文件
- **禁止**在仓库根目录留下未忽略的私有脚本目录（`scripts/*` 那条 gitignore 规则覆盖不到根目录，必须单独锚定）

## 允许行为

- `.gitmodules` 声明子模块地址。SSH 形式（`git@github.com:...`）需要部署密钥才能访问，不构成匿名下载入口
- 公开文档以 L1/L2 粒度描述路径、编码机制、同步流程
- 公开侧的钩子与部署脚本为完成职责写出必需的私有路径（`githooks/post-checkout`、`post-merge` 的 `SRC`/`DST`）
- 事故记录用文件名 + 行号做定位坐标，但**只写工程后果，不写业务后果**
- 私有仓库内部的任何文件可自由引用私有内容

以下内容在本规则收窄前已进入公开 git 历史。**删除 HEAD 里的副本并不能把它们从历史中移除**，整改的边际隐私收益接近于零，而损失的是项目自身的可用文档，故登记为豁免：

**豁免的边界**：

- 只冻结**现有文字**，不得在这些文件里**新增** L3 内容
- 新建的公开文件一律按 L1/L2 写
- 豁免文件若需大改，改动部分按新规则写，不回补旧的 L3 表述

## 修改原则

- 新增涉及私有仓库的公开内容前，先按 L1/L2/L3 判级
- 拿不准就降到 L2：只留路径与文件名，删掉用途描述
- 需要指引用户配置私有脚本时，用泛化描述，如"将你的游戏脚本放入 `scripts/` 目录"
- 子模块提交规则详见 `git-workflow.md`
